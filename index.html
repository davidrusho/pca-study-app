Reaching a private GKE (Google Kubernetes Engine) cluster from Cloud Build

Default Cloud Build workers run outside your VPC (Virtual Private Cloud); a private pool peers into it, and HA VPN carries traffic on to the control plane.

Keywords in the question

private cluster no public endpoint build workers cannot connect Cloud Build GKE control plane

On the exam

"Your Cloud Build triggers must run a step against a GKE cluster with no public endpoint." → Cloud Build private pool

Distractors

  • Cloud NAT (network address translation): outbound only; tempting when the need is actually inbound.

Peering is not transitive, so the pool and the control plane need an HA VPN between two of your VPCs. A DNS-based endpoint avoids the VPN.

Sources

"Cloud Build private pools and GKE cluster control planes both run in Google-owned VPC networks. These VPC networks are peered to your own VPC network on Google Cloud. However, VPC Network Peering doesn't support transitive peering, which can be a restriction when using Cloud Build private pools." "However, the GKE cluster control plane also runs in a Google-owned project and connects to your VPC network using Private Service Connect (PSC)... Configure VPC Network Peering for GKE 1.28 and below." per Google: Accessing private GKE cluster control planes from Cloud Build private pools.

Cloud NAT (Network Address Translation) is outbound only

Cloud NAT lets VMs with no external IP (Internet Protocol) reach the internet, outbound only.

Keywords in the question

no external IP private VMs need internet download updates

On the exam

"VMs with no external IP need to download OS updates; no inbound connections are required." → Cloud NAT

On the exam

"A workload needs 10 Gbps of dedicated, encrypted bandwidth to on-premises, without traversing the public internet." → Dedicated Interconnect with Cloud Router, encrypted with MACsec (or HA VPN over Interconnect)

"A production workload requires a 99.99% availability SLA for its connection back to the data center." → Critical production Interconnect, or HA VPN with two tunnels across both interfaces

Interconnect does not encrypt traffic by default. Add MACsec (Media Access Control security) on the Interconnect link, or run HA VPN over Interconnect, when a question says encrypted. per Google: Cloud Interconnect overview.

GKE (Google Kubernetes Engine) autoscalers

GKE has three autoscalers: VPA resizes pods, HPA changes pod count, cluster autoscaler changes nodes.

In this tab: VPA · HPA · Cluster autoscaler

VPA (Vertical Pod Autoscaler): changes the size of a pod

VPA resizes what a pod is allowed to use; pod count stays the same.

Keywords in the question

pods use 20-30% of requested CPU (central processing unit) over-provisioned right-size

HPA (Horizontal Pod Autoscaler): changes the number of pods

HPA adds or removes pod copies to match demand; every copy keeps its size.

Keywords in the question

traffic spikes more load scale out requests per second

Cluster autoscaler: changes the number of nodes

The cluster autoscaler adds or removes nodes based on pod requests, not actual usage.

Keywords in the question

pods Pending idle nodes add or remove nodes

On the exam

"Pods consistently use only 20-30% of their requested CPU." → VPA

"Pods are stuck in Pending because no node has room, even though other nodes show low actual use." → cluster autoscaler adds a node; fix inflated requests with VPA first

Sources

Google's GKE VPA documentation: VPA is for steady-state right-sizing, not sudden spikes. For spiky demand, use HPA. To use both on one workload, Google points to multidimensional Pod autoscaling, or HPA on custom or external metrics.

Bigtable row keys and hotspots

Bigtable splits rows by key range; a key starting with the time creates a hotspot.

Keywords in the question

Column family is a fixed group (sensor_data); column qualifier varies (sensor_type).

Cloud DNS (Domain Name System): who is asking, where do the records live?

Two questions pick the zone: who is asking, and where do the records live?

In this tab: A. The five zone types · B. Pick the zone · C. Distractors

A. The five zone types

The asker is usually a VM (Virtual Machine) in a VPC (Virtual Private Cloud) network, or an on-premises server. The arrow points from the asker to the answerer.

Keywords in the question

internal names, only these VPCs on-premises DNS is authoritative on-premises must resolve Google Cloud names another VPC already resolves it public website name

An outbound server policy is the other way to forward out. It names alternative name servers for the whole VPC network.

B. Pick the zone

Who asks, and who answers, decides the zone.

#FeatureWho asks → who answersExam keywordsQuick rule
1Private zoneVMs in authorized VPC networks → Cloud DNS, records you hostinternal names, only visible to these VPCsRecords live here.
2Forwarding zone (outbound forwarding)Your VPC → on-premises or other DNS servers (target name servers)on-premises DNS is authoritative for corp.example; records change on-premisesForwarding = OUT.

C. Distractors

Distractors

  • VPC Network Peering does not share private DNS zones automatically. Use a peering zone.
  • A forwarding zone does not let on-premises query you. That is the inbound server policy.
  • An inbound server policy does not make Google Cloud query on-premises. That is a forwarding zone.
  • A forwarding zone cannot reach its targets through transitive routing over VPC Network Peering. Use a peering zone to the VPC that holds the forwarding zone.
  • A private zone is not visible from the internet. Only a public zone is.

On the exam

"On-premises servers must resolve the private names of Compute Engine VMs over Cloud VPN." → inbound server policy

"VMs must resolve corp.example, which the on-premises DNS servers own." → forwarding zone

"A spoke VPC must resolve names that the hub VPC already resolves, without copying records." → peering zone

"A public zone is visible to the public internet, while a private zone is visible only from one or more Virtual Private Cloud (VPC) networks that you specify." per Google: Cloud DNS overview.

"Cloud DNS forwarding zones let you configure target name servers for specific private zones. Using a forwarding zone is one way to implement outbound DNS forwarding from your VPC network." "Instead of creating records within the zone, you specify a set of forwarding targets." "Cloud DNS cannot use transitive routing to connect to a forwarding target." per Google: DNS zones overview.

"DNS peering is a one-way relationship." "DNS peering and VPC Network Peering are different services. VPC Network Peering doesn't automatically share DNS information." "Lookups for records in the peering zone's namespace follow the DNS producer network's name resolution order." per Google: DNS zones overview.

"To make a VPC network's name resolution services available to on-premises networks that are connected to the VPC network by using Cloud VPN tunnels, Cloud Interconnect VLAN (virtual local area network) attachments, or Router appliances, you can use an inbound server policy." "Inbound server policy entry points are internal IPv4 addresses sourced from the primary IPv4 address range of every subnet in the applicable VPC network" (except subnets with specific purposes) per Google: DNS server policies overview.

"You can modify the Cloud DNS name resolution order of a VPC network by creating an outbound server policy that specifies a list of alternative name servers." per Google: DNS server policies overview.

Decision rules: situation, then answer

Short rules for exam day. Read the situation, find the row, take the answer.

In this tab: Identity · GKE autoscalers · Cloud Router · Encryption · IAM vs policy · Regional GKE · Egress vs PSC (Private Service Connect) · Managed tools

Who is asking? Pick the identity

Ask where the code runs first. Then ask whether an identity provider exists.

SituationAnswer
Code runs on Google Cloud (Compute Engine, Google Kubernetes Engine, Cloud Run)Attached service account. No key to store or rotate.
Code runs outside Google Cloud and an identity provider exists (AWS, Azure, GitHub, GitLab)Workload Identity Federation. A GitHub or GitLab pipeline deploying to Google Cloud is still outside.
Code runs outside Google Cloud and there is no identity providerService account key. This is the last resort.
A person needs time-limited access (for example, auditors for 14 days)IAM (Identity and Access Management) Condition with an expiry on request.time.

GKE (Google Kubernetes Engine) autoscalers by symptom

Name what is short or wasted, then pick the autoscaler.

SituationAnswer
Pods are OOMKilled, or requests do not match real use, and traffic is flatVPA (Vertical Pod Autoscaler). It resizes the pod's requests.
More traffic and the pods are overloadedHPA (Horizontal Pod Autoscaler). It adds pods.
Pods are Pending with Insufficient cpu, or nodes sit idleCluster Autoscaler. It adds or removes nodes.

Cloud Router

Cloud Router only exchanges routes. It never carries traffic.

SituationAnswer
What is it?The BGP (Border Gateway Protocol) control plane. It learns and advertises routes and has no data path.
When is it needed?HA (high availability) VPN (Virtual Private Network) and Cloud Interconnect VLAN (virtual local area network) attachments need one. Cloud NAT (Network Address Translation) relies on one for its control plane.
A question asks it to connect networks or filter trafficCloud Router does neither. Use peering or a hub to connect networks, and firewall rules to filter traffic.
Regional or global dynamic routing mode?Regional: routes learned in a region stay in that region. Global: the best path for each prefix is shared with all regions.

Encryption options: pick the lowest level the question requires

Each level adds control and effort. Stop at the first level that meets the requirement.

SituationAnswer
No key requirement, least effortGoogle default encryption.
Control rotation and key lifecycleCMEK (customer-managed encryption keys) in Cloud KMS (Key Management Service).
Hardware-backed keys, FIPS (Federal Information Processing Standard) 140-2 Level 3CMEK with Cloud HSM (hardware security module).
Keys must stay outside GoogleCloud EKM (External Key Manager).
Supply the key with each requestCSEK (customer-supplied encryption keys). It is a Cloud Storage feature. CSEK for Compute Engine is deprecated, so it is rarely the answer.

IAM, organization policy, or firewall policy?

Match the verb in the question: who may act, what is allowed, or what traffic passes.

SituationAnswer
Who may act on a resourceIAM (Identity and Access Management) role.
What is allowed, such as resource locations or external IPsOrganization policy constraint, for example compute.vmExternalIpAccess.
Block traffic such as SSH (Secure Shell) for one folderHierarchical firewall policy attached at the narrowest level named. The organization level is too broad.
Data must not leave, even with valid credentialsVPC (Virtual Private Cloud) Service Controls.
Separate permissions for dev, staging, and prodOne project per app per environment. The project is the IAM (Identity and Access Management) boundary.

Regional or multi-zonal GKE (Google Kubernetes Engine)?

The question is about the control plane.

SituationAnswer
The control plane must survive a zone outageRegional cluster. Its control plane has replicas in several zones.
A zonal cluster with nodes in several zones (multi-zonal)It still has one control plane in one zone. If that zone fails, workloads keep running but you cannot configure the cluster.
GKE AutopilotAlways regional.

Direct VPC egress or Private Service Connect?

Check the direction first: out of Cloud Run, or in to a service.

SituationAnswer
Cloud Run must reach private IPs in your subnet (outbound)Direct VPC (Virtual Private Cloud) egress. The Serverless VPC Access connector is the older path.
Reach one managed service privately through an endpoint IP (Internet Protocol) in your VPCPrivate Service Connect.
Requests coming in to Cloud RunThat is ingress. Use the ingress setting and a load balancer.

Managed version of the existing tool

When the team already runs a tool and the question says quickly or without rewriting, pick Google's managed version.

SituationAnswer
Prometheus metrics and PromQL (Prometheus Query Language) on GKE, no instrumentation rewriteManaged Service for Prometheus.
Existing Hadoop or Spark jobsDataproc (now Managed Service for Apache Spark).
Existing Redis cache: Memorystore for Redis or Valkey (Memcached is deprecated)Memorystore.
Existing MySQL, PostgreSQL, or SQL Server appCloud SQL. Use AlloyDB for faster PostgreSQL.
